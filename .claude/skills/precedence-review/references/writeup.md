# The expert write-up

A LaTeX report, titled "Missing citations in “⟨preprint title⟩”", for experts in the field who have **not read the preprint** and will **only read the PDF**. They must be able to check every claim against the two papers without reading the rest of the preprint. Each entry gives them a pointer the preprint doesn't: earlier work that already contains part of the preprint. Each entry also says plainly that the citation is missing, since that is the point of the exercise. Both are served by **precise correspondences**, not by tutorial prose, and by keeping each entry no longer than it is worth to the reader.

## Structure
```
reviews/<review>/writeup/
  precedence-findings.tex     main file: title, \input{parts/summary}, ToC, about, overview, Findings section, bibliography
  parts/preamble.tex          from <skill>/assets/preamble.tex (fixed macros and styling)
  parts/about.tex             from <skill>/assets/about.tex (what is reported, relationships, centrality, citations, flags, how to check, provenance)
  parts/overview.tex          written by you: the preprint in brief plus all shared notation
  parts/summary.tex           summary table (you write it at assembly)
  parts/bibliography.tex      generated by make_bib.py; never edit by hand
  findings/<finding>.tex      one fragment per finding, opening with \finding{<title>}{<finding>}
  findings/retired/           withdrawn, merged or "none" fragments (kept, not input)
  findings/pre-check/         backup before the apply-verdicts pass
  build/                      pdflatex output; build/full.txt is the pdftotext dump used for QA
```
The main file template is `<skill>/assets/precedence-findings.tex`.

**IDs are assigned by LaTeX, never typed.**
- The Findings `\section` is followed by `\findinggroup{F}`.
- Each fragment opens with `\finding{<title>}{<finding>}`, with the slug equal to its file name. This prints an unnumbered heading "F3. <title>", adds it to the table of contents, and defines `f:<finding>`.
- `\ref{f:<finding>}` prints the ID, as a link.
- IDs follow the order of the `\input` lines, which is the magnitude order: centrality (main result, central, supporting, peripheral), then the relationship (same result, same technique, adapted, proof shortcut, same route, fragment, weaker result), then reading order. The validator checks it.
- Withdrawing or reordering a finding means deleting or moving its `\input` line; every ID and reference follows. Only a summary-table row has to go by hand: a leftover row prints "??", and the build fails.

## Scaffolding (you, before launching drafters)
This can overlap with the last section pass.
1. **Copy `assets/preamble.tex`, `assets/about.tex` and `assets/precedence-findings.tex`.** Fill the placeholders in `about.tex`.
   - It explains what is reported, the relationship types, centrality, credit statuses, the two flags and the specific-content rule.
   - Use its no-companion sentence if there are no companions.
   - Put `% BIB OAI-...: <citation>` lines for the preprint and its companions at its top. Cite the release with `\url{…}`, never a long `\texttt` path, which overflows the margin.
   - The Provenance paragraph stays commented out until the publish step, so builds pass before then.
2. **Write `overview.tex` yourself** (`\section{The preprint in brief, and notation}\label{sec:overview}`). It gives the main theorem as the preprint states it, the proof routes as the preprint itself names them, and every piece of notation used by more than one finding. Drafters reuse it rather than redefining things.
   - Keep it tight; it is not the review's own account of the paper.
   - Don't include a section/page map; the preprint has its own table of contents.
3. **Test-compile** it with `bash <skill>/scripts/fragment_test.sh parts/preamble.tex parts/overview.tex <scratch>/overview-test`.
4. **List the findings** from `FINDINGS.md`, with the relationships, centralities and magnitude order you settled at consolidation.
   - Give each one a short slug, such as `kac-rice-complexity`, which becomes its file name.
   - Put their `\input` lines in the main file in magnitude order.
   - Pending merges are the user's decision: recommend one and ask. Launch the drafters the decision doesn't affect in the meantime.

## Drafting brief
Write the shared part to `<scratch>/writeup-brief.md`. Each agent's prompt is a pointer to that file ("read it completely first and follow it") followed by a `## YOUR FINDING` block. Launch all drafting agents **in parallel**, in the background.

````text
You are drafting ONE finding for a LaTeX report about a mathematics preprint, titled "Missing citations in “{TITLE}”". The readers are **human experts in the field who have not read the preprint and will only read the PDF**. Each finding points them to earlier work that already contains part of the preprint, and says plainly that the preprint doesn't cite it there. Readers must be able to check each claim against the two papers: precise statements, exact compiled locators, and correspondences laid out side by side. The document must be **concise**. Today is {TODAY}.

## Context
- **The preprint:** "{TITLE}" ({DATE}). TeX: `{PREPRINT_DIR}/build/sections/*.tex`; bibliography: `{BIBLIOGRAPHY FILE}`; compiled PDF: `{PREPRINT_DIR}/{PDF NAME}`.
- **Companions** (same release; not earlier work): {LIST WITH PATHS, OR "none"}.
- **Compiled-text extractions with page breaks** (`\f`; the page of a match is 1 plus the number of `\f` before it): `{SCRATCH}/paper.txt` and {COMPANION TEXT FILES}. Find compiled numbers with `python3 -I -X utf8 "{SKILL}/scripts/pagefind.py" <txt> "<regex>"`. Its `p.N` is the PDF page index. **Use printed page numbers,** which the script shows in each page's first and last lines; many sources have an offset.
- **Review materials:** `{REVIEW_DIR}`: `FINDINGS.md` (the digest), the section reports `NN-*.md`, and `CONSOLIDATION.md`, whose compiled-locator table for your finding is your starting point. They hold detailed correspondences and locators **but may contain errors**.
- **Source library:** `{REPO}/prior-work/` (`src/<Key>/` LaTeX where available, `papers/<Key>.pdf`, `text/<Key>.txt`). Grep `INDEX.md` for keys; don't read it whole.
- **The write-up:** `{WRITEUP_DIR}`. Read `parts/overview.tex` (shared notation; don't repeat it) and `parts/about.tex` (the definitions readers see). For the target form and length, look at `{SKILL}/assets/example-finding.tex`; copy its form, not its content.
- **Valid slugs for cross-references:** {ALL SLUGS}.

## Definitions (About has them in full)
- **Relationship:** same technique (reused essentially intact; new ingredients around it don't change that); adapted (structure followed, core changed); fragment (one piece of the technique); same route (an earlier paper proposed the strategy); same result; weaker result (weaker, special-case or partial-range); proof shortcut (a published result would replace a large part of the argument).
- **Centrality** (best-effort judgment): main result (the earlier work covers the main result itself, or most of it), central, supporting, peripheral.
- **Credit status:** not cited; cited for other content; credited elsewhere (not where it is used); credited in part. A citation counts only if it is for that specific content.
- **The one exception, overstated novelty:** the earlier work is cited, but the abstract or framing presents the content as new.

## Structure
```
\finding{<Title: a natural-language gloss of the technique or result, without citations>}{<SLUG>}
\paragraph{Summary.}
\paragraph{Setup.}
\paragraph{Role in the argument.}
\paragraph{The earlier technique.}   (or \paragraph{The earlier result.})
\paragraph{Correspondence.}
\paragraph{Differences.}
\paragraph{How to check.}
```
These headings are a menu, not a requirement: leave out any that doesn't apply, and reorder where that reads better. (A proof shortcut may use: Summary, Setup, Role in the argument, The earlier results, How the earlier results apply, What the route still contributes, How to check.)
- **Title.** A natural-language gloss of the technique or result, without citations: no author–year references and no work names. The summary table carries the works. Avoid en-dash chains of names, which don't break across lines.
- **Summary.** 4–6 sentences.
  - **The first two say what the earlier work is and that the preprint doesn't cite it for this content.** Variants: it cites it only for something else, or only elsewhere. For overstated novelty: where the preprint does cite it, and where the abstract or framing presents the content as new. Don't soften or bury this.
  - Then say where in the preprint (compiled locators), and give the relationship (`\rel{same technique}`) with a one-clause reason.
  - Describe the mathematics with verbs that fit the relationship: "follows", "adapts", "uses one step of", "carries out the route proposed in", "was first proved in".
- **Setup.** Only the local notation needed, with what each object means. Refer to Section~\ref{sec:overview} for shared notation.
- **Role in the argument.** A few sentences, including the chain of results the finding feeds, in compiled numbering ("Lemma 5.6 → Prop. 5.1 → Thm. 1.1"). Recurrences elsewhere go here in one sentence.
- **The earlier technique / result.** Its precise statement in the source's own notation, with locators: just what the reader needs to see the correspondence. Don't write tutorial explanations: readers learn the shared structure from the precise correspondences, and tutorial prose only adds length. If the source itself calls the device standard, or credits a third paper for it, say so with the locator.
- **Correspondence.** One table mapping objects and statements, each side in its own native notation, with compiled locators. Then the one or two key formulas side by side.
- **Differences.** A short list of local, checkable differences from the earlier work: new ingredients, a different object, a different proof of a step. Not the preprint's contributions in general; the preprint states those itself.
- **How to check.** An `enumerate` of 2–4 side-by-side checks with exact locations on both sides.

Length: **at most 3 pages**, usually 2–2.5 (a merged finding may use up to about 4). Entries may be shortened after a later check.

## Do not include
- a separate "citation status" paragraph (the Summary states it);
- **hedges.** If a claim doesn't hold, leave it out; don't qualify it. Facts that help a reader place the relationship (dates, what the source says about itself, what a cited work covers) are content, not hedges;
- **process notes:** no history of the finding ("reclassified", "originally a fragment"), no mention of reports, the library, agents, a review or check pass, searches, "not consulted", "merged", or checks a reader cannot reproduce;
- `[not verified: …]` markers: if you can't verify a claim, leave it out;
- irrelevant asides, source errata, history that doesn't serve the correspondence, or boxed notes;
- **TeX file names, TeX line numbers or TeX labels in the printed text** (see Locators);
- **the preprint's own reference numbers** ("[29]"). Refer to papers by author names plus `\cite`/`\sloc`;
- numbered table captions ("Table 3"). Say "the table below".

## If the finding doesn't hold
Re-verify every claim against the actual passages. The reports may be wrong; use the correct version and list corrections in your final message.
- **Write the finding with the assigned relationship and centrality.** If you think another fits better, propose it with reasons in your final message, not in the fragment. The coordinator decides.
- **Drop a component** whose correspondence fails, or that the preprint credits where it is used after all, and say so in your final message.
- **Withdraw only on facts:**
  - the correspondence fails at a specific step;
  - the source postdates the preprint;
  - the preprint credits the content where it is used after all (and doesn't overstate it);
  - the content is textbook material in exactly the form used: name the textbook passage;
  - the earlier work is a parallel: state the setting, the object, and why nothing suggests the preprint drew on it;
  - a factual error leaves nothing to write.

  Then title the fragment "[Withdrawn] …", and give the fact at the top of your final message.
- **Judgments are not grounds to withdraw:** "this is standard", "a cited later result supersedes it", "only a fragment". Write the finding, state the relevant facts, and leave the judgment to the later check.

The precise correspondences you write also feed that check, so precision about what does and doesn't match is valuable either way.

## Locators
- **Preprint and companion locations:** only via `\ploc{<compiled>}{<file:line>}`. The macro prints **only** the first argument, which must be a compiled section, equation, theorem/lemma/proposition number or printed page that a PDF reader can find, e.g. `\ploc{Lemma~5.2}{profile-spectral.tex:400--420}`, `\ploc{\S13.3, p.~98}{...}`, `\ploc{(5.27), p.~39}{stability.tex:...}`. Don't wrap the first argument in an extra pair of parentheses (`\ploc{((5.27), p.~39)}`); it prints doubled parentheses. Companion locations use the companion's own numbering and pages. Never write a file name, TeX label or line number anywhere else.
- **Sources:** `\sloc{<Key>}{Thm~2.6, p.~12}` or `\cite{<Key>}`, with `<Key>` exactly as in INDEX.md, and the printed page.
- **Names of works:** the authors' names or initials, as for any citation. When two works share an author list, give full names and keep an initialism for at most one.
- **"Section N" is ambiguous** between this report and the preprint. Write "the preprint's \S5" or use `\ploc`.
- **Works not in the library:** key `NL-<Name><Year>`, with one comment line `% BIB NL-<Key>: Authors, Title, Venue (Year), DOI` at the top of the fragment. Put only the citation on that line, never notes about how it was found or whether it was read.
- Never invent citations, numbers, quotes or formulas.

## LaTeX style
- Use only the macros in `parts/preamble.tex`: `\R \E \P \one \D \Lgen \Var \Cov \Ent \KL \Tr \ran \norm{} \ip{}{} \ploc{}{} \sloc{}{} \rel{}`. Define no macros. The build fails on primitives that read files, define macros or embed PDF actions (`\input`, `\def`, `\newcommand`, `\usepackage`, `\special`, `\pdf…` and the like). Never copy them from a source's LaTeX.
- **Lists:** plain `itemize`/`enumerate` with **no options**; the global settings handle spacing.
- **Structure:** no `\subsubsection`, no `\fbox`, no `\begingroup\sloppy`. If the title is long, give a short title: `\finding[<short title>]{<title>}{<SLUG>}`. Use `\texorpdfstring` for math in titles.
- **IDs:** never type a finding ID ("F3"). LaTeX assigns them. Refer to another finding as `finding~\ref{f:<its slug>}`, using the valid slugs above. In a standalone test the ID prints as "?1"; that is expected.
- **Tables:** `\begin{center}\small\begin{xltabular}{\linewidth}{...}` with booktabs rules, a header that repeats on every page (`\toprule <header>\\ \midrule \endfirsthead \toprule <header>\\ \midrule \endhead`), and **`\addlinespace` after every row** (not before `\bottomrule`).
- Escape special characters, use `--` for ranges, and no Unicode math. Wide displays: `gather*` or split lines.
- **End the fragment with a blank line.**
- **Edit the fragment only with the Write/Edit tools,** never via sed, heredocs or Python string replacement: backslashes get corrupted.
- **Test-compile:** from inside `{WRITEUP_DIR}`, `bash "{SKILL}/scripts/fragment_test.sh" parts/preamble.tex findings/<SLUG>.tex "{SCRATCH}/draft-<SLUG>"`. It exits 0 only when every check passes. Fix all `!` errors, forbidden strings, gate hits and any overfull box over 10pt (keep title lines well under it: the printed ID is wider in the full build). Undefined citations and references are expected in this standalone test. Remove each listed warning that isn't legitimate.

{TOOL PITFALLS BLOCK, WITH THE SCRATCH SUBFOLDER `{SCRATCH}/draft-<SLUG>/`}

## Output
- Write exactly one file: `{WRITEUP_DIR}/findings/<SLUG>.tex`. Modify nothing else; don't download anything or edit INDEX.md.
- Final message, under 150 words:
  - the file path and page count;
  - any proposed change of relationship or centrality, with reasons (or [Withdrawn] with the fact);
  - dropped components;
  - corrections to the reports;
  - `NL-` entries;
  - proposed summary-table cells (Technique or result / In the preprint / Cited?).
````

**The `## YOUR FINDING` block** gives, for one finding:
- **Header line:** the slug, which is also the file name; the relationship and centrality; and "overstated novelty" with the claim's location where it applies. Add the slugs of any findings it should cross-reference.
- **Suggested title:** a natural-language gloss, without citations.
- **What it is.** The technique, its earlier source(s) with library keys and main locators, principal source first; where the preprint uses it (file:line, so the agent can find it fast); what the preprint does and doesn't cite; and the dependency chain from consolidation.
- **Materials.** Which section reports and which findings in them; recurrence locations to mention in one sentence; relevant credit-map entries; consolidation corrections, written as explicit don'ts ("do not describe X as applying this device").
- **Specific checks.** Anything the agent must verify. For example: does a cited source cover it? For a proof shortcut, check normalizations, hypotheses, and that the claimed independent route really is independent; grep its sections for references into the other route.
- **Expected objections, as factual questions only.** If there is an obvious objection, turn it into checks of its factual premise: "Is this step credited to its source at the point of use?", "Is this exact form in a textbook? Name the passage." Don't add "feel free to withdraw", or ask the drafter to rule on whether the objection justifies omission: that wording leads drafters to withdraw findings on judgment calls.

## Processing drafting hand-backs
- **Log each one in a short line:** the page count, any proposed change of relationship or centrality, dropped components. Proposals go into `FINDINGS.md`; you decide them after the persona check.
- **A withdrawn finding:** delete its `\input` line, move the fragment to `findings/retired/`, and grep `f:<finding>` in every other fragment and in `summary.tex`, removing the references. Tell the user the fact behind it.
  - If the user asks, or you can't confirm the fact yourself, run a blind persona check on the original claim (`skeptic.md`).
  - If that check affirms inclusion, ask the user whether to reinstate it as a late finding.
- **Report corrections the drafter found:** fold them into `FINDINGS.md`.
- **Two findings overlapping, or "is X just Y twice?":** ask the user. Give numbered options (merge / keep separate / drop one as a component of the other) and your recommendation. If they choose a merge, one agent rewrites the surviving fragment, integrating each paragraph rather than appending. The cap is about 4 pages. The other fragment goes to `retired/`.
- **A late finding** (from a resumed section agent or a user lead): give it a new slug, put its `\input` line where its magnitude puts it, tell the user that IDs after it shift, add it to the slug list, and launch a drafter.

## Assembly
1. **Check the main file's `\input` order** against magnitude: the relationships and centralities you set at consolidation, or, after the apply-verdicts pass, as you settled them. This order fixes the IDs.
2. **Build once,** so that the `.aux` file holds the IDs.
3. **Write `parts/summary.tex`.** Collect each finding's ID, slug, title and Summary with `python3 -I -X utf8 <skill>/scripts/print_summaries.py <writeup dir>`, which reads the IDs from the last build. Drafters' proposed cells are a good start. See `assets/summary.tex`.
   - It is an unnumbered "Summary of findings" section with a short lead-in that says each row is a missing citation.
   - The table is a `\footnotesize` xltabular with columns **ID | Relationship | Centrality | Technique or result | In the preprint | Cited?**.
   - Each row starts with `\ref{f:<finding>} & \rel{<relationship>} & <centrality> &`, in that order; the JSON validator reads those cells. `\ref` prints the ID as a link; never type an ID.
   - The **Cited?** cell names the earlier works as "Authors Year \cite{Key}", in the same form as the README's "Earlier work" column. It follows them with what the preprint cites ("Author--Author 2018 \cite{…}: not cited"), then `\attrgap` and `\overstated` where the flags apply.
   - Put `\addlinespace` between rows. End with `\clearpage`.
4. **Build again** (see QA gates below).
5. **Look at the PDF.** Use Read with `pages` on the summary table and on one or two correspondence tables, to catch layout problems such as big gaps, crowded rows or headerless continuations.
6. **Copy the result.** Copy `build/precedence-findings.pdf` to `writeup/precedence-findings.pdf`, and send that copy to the user, with a file-sending tool if you have one, otherwise by giving its path. Before any author-persona agents read it, also dump its text to `build/full.txt`.

## QA gates (every build that goes to the user)
Run `bash <skill>/scripts/build.sh <writeup dir> <repo>/prior-work/INDEX.md precedence-findings.tex`. It exits 0 only when every hard gate passes, and prints `result: PASS` or `result: FAIL (<reasons>)`. On PASS it stamps the build, and `publish_prep.sh` publishes only a stamped build.

Hard gates:
- **Bibliography:** `make_bib.py` succeeds: no missing key, no malformed INDEX row, no missing `\input` file.
- **TeX source:** the lint `tex_gate.py` finds no file-reading, macro-defining or PDF-action commands in the parts and fragments, and the main file inputs only `parts/` and `findings/`.
- **pdflatex:** it exits 0 with no `!` errors and produces a PDF. It runs confined (`tex_sandbox.sh`): it can't read or write outside the write-up folder or run programs, and a run that loops is stopped. The build first checks that the installed TeX honors this. If that check fails, stop and tell the user; don't compile another way.
- **PDF objects:** `pdf_check.py` finds nothing but text, internal links and `http(s)` links: no other action, annotation, attachment or form.
- **References:** no undefined reference or citation. This includes `\hyperref` targets and warnings wrapped in the log.
- **Layout:** no overfull box over 10pt.
- **Forbidden strings:** no hit from `scripts/forbidden-patterns.txt` in the PDF text: `.tex` names, `tex:` locators, TeX labels, `??`, `[?]`, "missing bibliography entry". Phrases broken across lines are caught too.

Review by hand (printed, not failing):
- **Warning patterns:** hits from `scripts/warning-patterns.txt`, such as process words ("skeptic", "regrad", "citation status", "caveat", "not verified", "library", "Table <n>") and note words. Remove each one unless it is legitimate, for example a book series called "… Library".
- **Doubled parentheses in `\ploc`:** the scripts list every `\ploc{((` in the TeX source. Fix each one.
- **Kept parentheticals:** the list `make_bib.py` prints of wordy parentheticals it kept in the bibliography.
- **Changed claims:** for any finding whose claim just changed, a targeted grep for the removed wording.

The rules for the document as a whole are in SKILL.md, "Rules for the expert write-up"; the drafting brief above carries them.
